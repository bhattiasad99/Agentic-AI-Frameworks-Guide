# Discovery and Launch Strategy

This project should earn reach by being repeatedly useful. Metadata and distribution help people discover that value; they cannot replace it.

## Positioning

**Category:** practical curriculum and decision guide  
**Audience:** software developers, technical leads, founders, and teams adopting coding agents  
**Promise:** learn the engineering systems behind reliable AI-driven development, compare frameworks honestly, and complete a verified first workflow

## Recommended repository description

> A practical roadmap and curated starter guides for AI-driven development: agentic coding, context engineering, spec-driven workflows, verification, and autonomous coding agents.

## Keyword architecture

| Intent | Terms | Natural placement |
|---|---|---|
| Learn the field | AI-driven development, agentic coding, AI coding agents | Title, opening promise, roadmap |
| Solve context problems | context engineering, AGENTS.md, Cursor rules, Agent Skills | Concepts and checklist |
| Plan reliably | spec-driven development, PRD, product requirements | Framework table and SDD guide |
| Execute work | coding-agent orchestration, multi-agent development, autonomous coding | Advanced roadmap and framework pages |
| Tool-specific | Cursor, Claude Code, Codex, GitHub Copilot, Windsurf | Starter guides and learning paths |

Use synonyms where they help readers. Do not repeat keywords where they do not add meaning.

## Launch sequence

1. Publish a tagged `v0.1.0` release with a concise changelog.
2. Set the repository description, topics, website/social preview, and Discussions if maintainable.
3. Share one concrete artifact, not “I made a list”: the framework decision matrix or learning checklist.
4. Write a LinkedIn post explaining one non-obvious insight: frameworks solve different layers and should not all be combined.
5. Invite upstream maintainers to correct their page—without asking for promotion.
6. Submit to relevant curated directories only after the guide has matured and real contributors have reviewed it.
7. Turn frequent questions into issues labeled `good first issue` and `help wanted`.

## Sustainable growth loop

```text
useful guide → real feedback → sourced correction → visible release
            → trustworthy sharing → new contributors → better guide
```

## Metrics worth tracking

- returning contributors;
- accepted corrections from framework users or maintainers;
- referral traffic to learning and comparison pages;
- issue-to-resolution time;
- broken-link and stale-command rate;
- stars-to-contributors ratio over time.

Do not buy stars, mass-tag maintainers, or manufacture engagement. Those tactics damage the exact credibility this project is meant to build.
