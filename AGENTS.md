# Repository Instructions

## Purpose

This repository is a curated, practical learning guide to frameworks and practices for building software with AI coding agents.

## Editorial standard

- Optimize for reader decisions and runnable learning, not list size.
- Explain why an item is useful and when it should not be used.
- Prefer first-party repositories, official documentation, and release notes.
- Verify current commands before editing a starter guide.
- Record the verification date as `Upstream checked: YYYY-MM-DD`.
- Never invent installation steps when upstream instructions are gated, missing, or ambiguous.
- Label inference and opinion; do not present them as upstream claims.
- Avoid hype, unexplained jargon, keyword stuffing, and star-count rankings.

## Structure

- `README.md`: visual entry point and navigation.
- `docs/learning-roadmap.md`: hands-on curriculum.
- `docs/choose-a-framework.md`: decision matrix.
- `docs/frameworks/`: one sourced starter guide per framework.
- `docs/concepts/`: tool-neutral engineering foundations.
- `docs/maintainers/`: editorial and discovery policies.
- `.github/`: contribution and issue templates.

## Definition of done for documentation changes

- Relative links resolve with correct case.
- External links use HTTPS and point to the most direct first-party source.
- Commands match current upstream documentation.
- Tables render correctly.
- New framework pages include limitations and a first exercise.
- README and framework index are updated when scope changes.

## Boundaries

- Do not run or recommend unreviewed remote installers as verification.
- Do not expose API keys, credentials, or private contact data.
- Do not present retrieval-based memory as reinforcement learning.
- Do not merge automated bulk additions without human curation.
