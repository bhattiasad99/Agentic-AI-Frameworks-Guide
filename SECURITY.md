# Security Policy

This repository is documentation, but installation commands, plugins, skills, hooks, and MCP configurations can still create security risk.

## Reporting a problem

Use GitHub’s private vulnerability reporting feature when available, or contact the repository owner privately through the contact options on their GitHub profile.

Do not open a public issue containing:

- credentials or tokens;
- a currently exploitable malicious link or installer;
- private repository information;
- instructions that could harm users before a correction is available.

For ordinary broken links, outdated commands, or non-sensitive corrections, use the documentation correction issue template.

## Reader safety

- Inspect remote installation scripts before running them.
- Prefer pinned releases over an unreviewed moving branch.
- Review files added by framework installers.
- Give coding agents least-privilege permissions.
- Never paste production secrets into chat or committed configuration.
- Keep human approval around destructive or production actions.

This guide summarizes upstream workflows; the security policy and release notes of each upstream project remain authoritative.
